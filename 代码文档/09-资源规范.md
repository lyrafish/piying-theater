# 09 · 资源规范 `assets/` `vendor/` 与原始素材

> 换图、换字体、换模型时看这一篇。**命名错一个字母，页面就少一块**，且往往不报错。

---

## 一、目录总览

```
piying/
├─ 故事/                原始素材（15 张 jpg：10 张人物 + 5 张背景）—— 不直接上屏
├─ 自定义人物/          原始素材（10 张 jpg）
├─ 自定义背景/          原始素材（10 张 jpg）
├─ 页面背景.jpg         原始素材
├─ 例图.jpg             参考图（不上屏）
├─ 参考.mp4             效果参考（不上屏）
│
├─ assets/              ← 构建产物，页面真正加载的东西
│  ├─ bg/page-bg.jpg           1 张，页面背景
│  ├─ stories/*.jpg            5 张，经典剧目布景
│  ├─ chars/*.png             20 张，抠好的透明皮影
│  └─ bgs/*.jpg               10 张，自定义布景
│
└─ vendor/              ← 第三方运行时，不要动
   ├─ mediapipe/
   │  ├─ vision_bundle.mjs             主 bundle（~1MB）
   │  ├─ hand_landmarker.task          手部模型
   │  └─ wasm/vision_wasm_internal.{js,wasm}  + nosimd 版（合计约 18MB）
   └─ fonts/*.woff2                    5 个，共约 820KB
```

**原始素材 ≠ 上屏素材。** 页面从不引用 `故事/`、`自定义人物/` 等目录，
只引用 `assets/`。所以换图后**必须重跑 `tools/build_assets.py`**（或手工把图处理成同规格放进 `assets/`）。

## 二、`assets/chars/*.png` —— 皮影人物

### 规格要求

| 项 | 要求 | 原因 |
| --- | --- | --- |
| 格式 | **PNG，带 alpha** | 要透明底，叠在布景上 |
| 内容 | 人物**完整入画**，四周留 2~5% 空隙 | 裁到包围盒后，贴边的图会让 `_layout` 的宽高比失真 |
| 背景 | 已抠净，**边缘不能有白边/绿边** | `build_assets.py` 有去污染步骤，手抠的图没有 |
| 朝向 | **正面或微侧**，双臂大致张开 | 骨架提取靠"找左右极值"，抱臂/背手会提取失败 |
| 姿态 | 站立，双腿分开 | 分叉点定位依赖双腿之间有背景空隙 |
| 尺寸 | 高 800~1600px | 太大浪费显存，太小第四幕放大后糊 |
| 颜色 | 皮影本色（半透明暖黄 + 黑轮廓） | 片元着色器会再加暖色，底图太黄会过曝 |

### 命名规则

| 类别 | 命名 | 例 |
| --- | --- | --- |
| 经典剧目人物 | **中文角色名**，与 `rig.json` 的 key 一致 | `项羽.png` `虞姬.png` `孙悟空.png` |
| 自定义人物 | `c01` ~ `c10` | `c01.png` |

> 中文文件名在 URL 里会被自动百分号编码，浏览器和 `serve.py` 都能正确处理，**不需要改成拼音**。
> 但**不要用空格、括号、`#`、`?`** —— 这些字符会破坏 URL 解析。

### 当前 20 个

```
经典剧目（10）：项羽 虞姬 孙悟空 白骨精 唐太宗 杨贵妃 梁山伯 祝英台 牛郎 织女
自定义（10）  ：c01 c02 c03 c04 c05 c06 c07 c08 c09 c10
```

## 三、`assets/stories/*.jpg` —— 经典剧目布景

| 项 | 要求 |
| --- | --- |
| 命名 | 与 `STORIES[].title` **完全一致**：`霸王别姬.jpg` `三打白骨精.jpg` `新贵妃醉酒.jpg` `梁祝.jpg` `鹊桥相会.jpg` |
| 尺寸 | 建议 16:9 或更宽，≥1600px 宽 |
| 内容 | 舞台中下部要有**人物站立的空间**（第三幕人物 `bottom: 3%`，第四幕 `bottom: 6.5%`） |
| 色调 | 暖、暗、有纵深；太亮的背景会把皮影吃掉 |

`object-position: center 46%`（第三幕）/ `center 44%`（第四幕）—— 裁切时保留下半部分。

## 四、`assets/bgs/*.jpg` —— 自定义布景

| 项 | 要求 |
| --- | --- |
| 命名 | `b01` ~ `b10` |
| 尺寸 | 4:3 ~ 16:9 均可，≥1200px 宽 |
| 用途 | 第三幕右侧网格缩略（`object-fit: cover`）+ 第四幕全屏底图 |

## 五、`assets/bg/page-bg.jpg`

**只有一张**，被第一、二、三幕复用（`object-fit: cover; object-position: center 42%`）。

⚠️ 这张图还兼任 **`file://` 自动跳转的探针**（`index.html` 里的 `AUTO.probeUrl`）。
**改文件名会导致自动跳转失效**——如果确实要改，同步改 `index.html` 里那一行。

## 六、`vendor/mediapipe/` —— 不要动

| 文件 | 大小 | 说明 |
| --- | --- | --- |
| `vision_bundle.mjs` | ~1MB | MediaPipe Tasks Vision 的 ES Module 入口 |
| `hand_landmarker.task` | ~7MB | 手部 21 点检测模型 |
| `wasm/vision_wasm_internal.js` + `.wasm` | 9MB | SIMD 版运行时（现代浏览器用这个） |
| `wasm/vision_wasm_nosimd_internal.js` + `.wasm` | 9MB | 非 SIMD 回退版 |

`hand.js` 里只写了 `FilesetResolver.forVisionTasks('vendor/mediapipe/wasm')`，
MediaPipe 会自己根据浏览器能力挑 SIMD / 非 SIMD，**不要手动改这个路径**。

> 这 18MB 是"完全离线"的代价。想瘦身可以删掉 `nosimd` 两个文件（省 9MB），
> 但老浏览器（Chrome < 91 / Safari < 15）就没法用手部捕捉了。

### 缺字的表现与处理

| 现象 | 处理 |
| --- | --- |
| 某个标题字显示成 □ | 该字不在子集里 → 重跑 `python tools/build_fonts.py` |
| 整段正文变方块 | `PiyingSong` 子集缺字 → 同上 |
| 字体完全不生效 | 检查 `css/fonts.css` 的 `src` 路径（相对 `css/` 目录，是 `../vendor/fonts/…`） |

## 八、性能预算

| 项 | 当前 | 说明 |
| --- | --- | --- |
| 首屏必需 | ~1.5MB | `index.html` + 2 个 css + 5 个字体 + 背景图 |
| 第四幕额外 | ~19MB | MediaPipe 的 wasm + 模型（**首次进入时加载，之后浏览器缓存**） |
| 皮影人物 | 每张 0.5~2MB | 两张 = 最多 4MB，第三幕已预载部分 |
| 显存 | 每人物约 8~16MB | 2048 以内的纹理 + 网格顶点 |

**优化建议**（如果加载慢）：

1. 把 `assets/chars/*.png` 压到高度 1200px（`build_assets.py` 里加一句 resize）；
2. 布景 jpg 的 `quality` 从 90 降到 82；
3. 删掉 `vendor/mediapipe/wasm/` 里 `nosimd` 的两个文件；
4. 在 `main.js` 的 `preload` 数组里减少预载项。

## 九、换素材的完整检查清单

换完图之后，按这个顺序过一遍：

- [ ] 图片放进 `故事/` / `自定义人物/` / `自定义背景/`（**原始素材目录**）
- [ ] 跑 `python tools/build_assets.py`
- [ ] 看控制台输出，确认每个人物都是 `light` 或 `dark` 模式（出现"背景复杂 -> 不抠图"说明抠底失败）
- [ ] 跑 `python tools/preview_rig.py`，看骨架是否贴合
- [ ] 骨架不对 → 手工改 `data/rig.json` 的 15 个坐标（归一化 0~1）
- [ ] 在 `js/data.js` 里登记名称与路径（自定义人物/布景）
- [ ] 新文案里有生僻字 → 跑 `python tools/build_fonts.py`
- [ ] 刷新页面，逐幕检查：封面 → 择幕 → 剧目 → 演绎
- [ ] 第四幕特别注意：影人是否完整、手脚是否跟着手指动、有没有网格撕裂
